# Caja to kitchen local integration

Local-only HTTPS Worker harness with D1 migration 0006 supports admin station assignment, order-time kitchen snapshots, kitchen reads and versioned item status changes with atomic status audit. New orders containing a product with no assigned station are rejected. Existing orders are not migrated to kitchen. Station changes increment catalog revision; the order snapshot and station rows are inserted transactionally with the order. State changes require a matching version and cannot revert Ready. Kitchen API strips price, tax and payment fields. Same order ID is rejected on duplicate; client recovery after timeout must retrieve the original order before retrying, and payload equality/replay semantics are not implemented.

Wrangler local D1 integration test `test/caja-kitchen-integration.cjs` created a latte with caramel and a waffle via POST /api/orders, checked server total $17.24, checked each station via two independent sessions, marked latte Ready, observed Ready from the second session, rejected a stale write and unauthorized/admin routes. Fixture setup is local test-only. HTTPS uses self-signed certificate with verification disabled only for the local test. This test makes API requests; it does not run the actual POS interface or a real Android browser.

`kitchen/live.html` is a local experimental browser page that polls every five seconds and retries after errors. Browser and reconnect behavior have not been validated, and localhost endpoint/allowlisted origin need a correctly configured local HTTPS host before use. Existing POS HTML is NOT connected to the API; Print Kitchen Ticket is NOT integrated, printed-ticket duplicate prevention is NOT implemented, and no physical device was tested. The display has no pagination or completed-order filtering: its 500-row cap can hide later orders. Do not use for customer orders. Kitchen roles are currently generic employee permissions and no station-specific authorization exists.

The API is restricted to local_test and 127.0.0.1; the Worker deploy entry remains locked. Local source limiter is shared and not an Internet IP rate limiter. Auth, CORS, CSRF, employee onboarding, token storage, rate limiting and audit coverage need remote security review. Changes to status record actor atomically, but attempt uncertain attribution remains separate. No public deployment or remote migration. See LOCAL-HTTPS-INTEGRATION.md for migration prerequisites, identity and backup; 0006 must be reviewed as additive and existing products must be assigned stations before creating orders.
