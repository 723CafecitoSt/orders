# Order retry security — local tests

Migration 0008 adds a SHA-256 fingerprint of the canonical order request. New requests store that fingerprint with the immutable server-priced snapshot. Retrying the same order ID by the same employee with identical request content returns the original snapshot, even if the catalog changed. A changed request or different employee is rejected. Concurrent identical requests produce one order; server total mismatches reject before insertion. Existing historical rows receive NULL and cannot be automatically replayed; they are not altered or repriced. The local POS adapter submits the same ID and request on retry rather than treating an arbitrary existing order as equivalent.

19 Node tests passed. Wrangler HTTPS and local D1 tests with migrations 0001–0008 passed including concurrent order requests, conflicting data, station routing and unauthorized kitchen access. HTTPS tests used a self-signed local certificate with verification disabled only inside local test process. No phone, browser UI, production payment or real Square Sandbox interaction was tested. The Worker remains deliberately locked.
