# Kitchen and printer local prototype

The `kitchen` directory is a separate demonstration. It is not integrated with the published POS, D1 or authentication. Its sample orders and item states exist only in memory on that browser; there is no synchronization or delivery guarantee. Changing stations separates beverages from food. Browser print creates an 80mm kitchen ticket with no payment information, and requires a compatible printer known to the Android print system. The BLE adapter is a tested code primitive, not connected to a button; a known BLE service UUID, writable characteristic UUID, printer byte encoding, chunk behavior and an ESC/POS capable printer must be independently verified. Only a user gesture may initiate Chrome's Bluetooth device selection. No printer or physical phone has been tested.

Do not use this prototype to prepare customer orders. Remote kitchen needs authenticated station access, a server-side product station field and immutable snapshots, idempotent order-to-station delivery, durable item states, ordering, duplicate suppression, offline and reconnect handling, no payment/customer fields and security review. Until implemented, no promise is made that orders or printed tickets are delivered exactly once. The separate published Worker remains locked, and the existing POS remains in simulation mode.

Wrangler HTTPS local test and 19 Node tests passed. HTTPS test uses a self-signed certificate with verification disabled solely in the local test process; this does not validate an Internet deployment. Browser visual testing and physical printing have not occurred. The previously documented backend security issues, including complete actor-aware audit, public rate limits, onboarding, remote session/CORS design and verified reconciliation, remain open. See LOCAL-HTTPS-INTEGRATION.md for the remote migration review; no remote migration or deployment is authorized.

Printer candidates to investigate, not purchase recommendations: MUNBYN P047 (80mm WiFi/USB) and P072 (80mm USB/LAN) are ESC/POS receipt printers, not confirmed BLE Web Bluetooth printers. Their use through Android Chrome's normal print dialog without a third-party app or bridge is not established. Confirm official Android print-service compatibility and test before buying. For a BLE model, obtain manufacturer documentation specifying GATT print service, writable characteristic, ESC/POS compatibility and 80mm media; Bluetooth and iOS/Android support alone do not prove Web Bluetooth printing works.
