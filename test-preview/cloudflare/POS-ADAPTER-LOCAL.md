# POS local integration status

In `test-preview/index.html` the existing Save button has an experimental adapter activated only on https://test.localhost with ?localApi=1. Default UI, local history, simulated payments and production remain unchanged. The adapter asks for employee credentials, uses the local-only API, verifies product and modifier IDs against the D1 catalog, saves a unique request identifier in separate localStorage before POST and looks up that ID on retry. It compares the server total to the locally displayed total and records the server snapshot in the local test history only on match. Request timeout leaves a pending entry instead of creating a new ID. This is not ready to use: the in-progress cart is not restored after refresh, matching product IDs and modifier groups must be provisioned in D1, tax overrides do not yet work, server-generated human order numbers, order notes and accurate reconciliation need implementation. The server rejects a total mismatch before inserting the order. If a response is lost, check the saved order ID before any new submission.

Kitchen endpoint now sorts newest changes first before its 500-row cap, so new orders are not hidden behind older entries, but pagination/retention and multiple-order consistency remain unfinished. The isolated kitchen page is not verified with the real POS, browser, phone or printer. No station-specific employee roles or printing-attempt deduplication were added. No live POS->D1->kitchen browser test has run; do not describe API-only results as browser verification. No migration or deployment of this experimental code is authorized.

19 existing Node tests passed and the modified inline script passed syntax checking. Existing local API tests from earlier work covered kitchen routing, not this adapter. An actual browser is required to complete the mandatory end-to-end test; this environment provides a Playwright library but a browser executable was not found in the initial check. Before remote testing, fix all noted issues, add station access control and print audit, use a secure bounded session and rate limiter, review retry identity and ensure audit completeness, then test through an actual browser and D1 local. No Square payments are connected.
